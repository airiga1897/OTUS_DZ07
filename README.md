# ДЗ07. Централизованный сбор логов в Elasticsearch

## Цель работы

Развернуть отказоустойчивый кластер Elasticsearch, собрать журналы веб-сервера,
БД и балансировщика и предоставить их просмотр в Kibana.

## Реализованное решение

Четыре ВМ Selectel: три отдельных узла Elasticsearch и app с Django-порталом,
источниками логов и Kibana. Filebeat установлен на каждой ВМ. Terraform создаёт
инфраструктуру, Ansible настраивает службы, Python управляет жизненным циклом
и проверками. [Задание](docs/assignment.md) и [соответствие требованиям](docs/assignment-review.md).

## Архитектура

| Узлы | Компоненты | Параметры одной ВМ |
| --- | --- | --- |
| app | HAProxy, Nginx, Django/uWSGI, PostgreSQL 16, Kibana 8.19.0, Filebeat | 4 vCPU, 8 ГиБ RAM, диск 20 ГБ |
| es1, es2, es3 | Elasticsearch 8.19.0, Filebeat; роли master/data/ingest | 2 vCPU, 8 ГиБ RAM, диск 20 ГБ |

HAProxy принимает HTTP на порту 80 и передаёт запросы локальному Nginx,
затем Django/uWSGI. PostgreSQL слушает loopback. Публичный IP есть только
у app; Kibana на порту 5601 и SSH на порту 22 доступны с разрешённых /32.
Elasticsearch использует HTTPS и транспортный TLS; напрямую из Интернета
он недоступен. [Схема и потоки данных](docs/architecture.md).

По умолчанию ES-узлы размещаются на разных физических хостах. В одном пуле
все ВМ используют общую приватную сеть без Глобального роутера. При размещении
между пулами он подключается после проверки совместимости, доступа и квот.
Работающие ВМ и сети сохраняются. [Подбор и ограничения](docs/placement.md).

Основа приложения включена в репозиторий из опубликованного ДЗ06:
[источник](config/upstream.json). Другие клоны для работы не требуются.
Начальные данные подготовлены по материалам ДЗ04 и загружаются Django-фикстурой.
Схему создают миграции; постоянный маркер в БД предотвращает повторную загрузку
поверх пользовательских данных. Media хранятся отдельно от исходников.

## Пошаговое развёртывание и проверка

Все команды выполняются локально в PowerShell 5.1 или 7 из корня клона ДЗ07.
Нужны Git, Python 3.12 с Windows launcher `py` и Terraform с поддержкой `terraform test`.
Создайте собственный проект Selectel и сервисного пользователя с ролью `member`
в этом проекте. Для межпулового размещения и работы с уже созданным Глобальным
роутером дополнительно нужна `global_router.admin` в области аккаунта.
Расширенный поиск при утрате контекста также требует чтения общих ресурсов.
Проверки владельца в коде не заменяют ограничения IAM.

Номер аккаунта находится в профиле панели Selectel, UUID проекта — в его
карточке. Имя и пароль задаются сервисному пользователю в IAM. Вводите
собственные значения по запросам `env.ps1`; реальные реквизиты в примеры,
`.env` и Git не записываются.

Однократная подготовка локального виртуального окружения и инструментов:

```powershell
.\scripts\setup.ps1
# Если Terraform отсутствует в PATH, вместо команды выше:
# .\scripts\setup.ps1 -TerraformPath C:\Tools\terraform.exe
```

Подготовка создаёт `.tools/venv`, собственную копию Terraform и `.env` из
[.env.example](.env.example); существующие настройки сохраняются.
В `.env` задаются только несекретные параметры. По умолчанию предпочтения —
ru-2 → ru-9 → ru-3, затем остальные разрешённые совместимые пулы.
Диски выбираются по маскам Universal → Basic SSD с проверкой сегмента через API.
[Все параметры и исключения](docs/run-settings.md).

**1. Ввести реквизиты в текущую сессию.** Пароль вводится скрыто;
для проверяющего запись реквизитов в файл не требуется.

```powershell
. .\scripts\env.ps1
```

Для разработки можно явно выбрать сохранение или загрузку файла:

```powershell
. .\scripts\env.ps1 -SaveLocal
# В новой сессии вместо ручного ввода:
. .\scripts\env.ps1 -Development
# Равнозначное сокращение: -Dev
```

`-SaveLocal` и `-Development` взаимоисключающие. PowerShell проверяет права
`.local/operator.json`; Python и Terraform читают реквизиты только из окружения.
Единая схема — [config/selectel-auth.json](config/selectel-auth.json).

**2. Развернуть и оставить стенд работающим.** Предварительные проверки входят в deploy.

```powershell
.\.tools\venv\Scripts\python.exe scripts/lab.py deploy
```

**3. Проверить сайт, логи, Elasticsearch и Kibana.**

```powershell
.\.tools\venv\Scripts\python.exe scripts/lab.py verify
```

**4. Показать адреса и открыть сайт.** Команда проверяет локальные state/context
и не требует облачных реквизитов. Kibana доступна по адресу app:5601;
пользователь — `elastic`, созданный пароль находится в `.local/secrets.json`.
Для входа используется поле `elastic`; поле `kibana` — служебный пароль
`kibana_system`, он не предназначен для входа в браузере. Скопировать пароль
в буфер обмена без вывода в консоль:

```powershell
(Get-Content .\.local\secrets.json -Raw | ConvertFrom-Json).elastic | Set-Clipboard
```

Вставьте его в форму входа Kibana. Файл содержит секреты стенда;
не публикуйте его и не прикладывайте к отчётам.

```powershell
.\.tools\venv\Scripts\python.exe scripts/lab.py open
```

**5. Повторно применить конфигурацию.** Размещение, ID и данные сохраняются;
изменения, удаление и замена существующих ресурсов блокируются проверкой плана.

```powershell
.\.tools\venv\Scripts\python.exe scripts/lab.py deploy
```

**6. Отдельно удалить стенд и подтвердить очистку через state и API.**

```powershell
.\.tools\venv\Scripts\python.exe scripts/lab.py destroy
```

При ошибке deploy стенд не уничтожается автоматически. При ошибке удаления
сохраняются state, контекст и ключи для повторного destroy. После подтверждённой
очистки служебные файлы удаляются; реквизиты разработки сохраняются до отдельного
решения пользователя. [Эксплуатация и восстановление](docs/operations.md).

## Доставка файлов

Основной способ для сдачи — GitHub Releases: ВМ скачивают архив исходников
и пакеты по HTTPS, проверяя размеры и SHA512. Доступ к S3 автора не требуется.
[Инструкция чистого клона и подготовки выпуска](docs/releases.md).

Для проверяющего подготовлен выпуск `v1.1.1` с проверенными исходниками.
Привязка к точному архиву сохраняется отдельным коммитом после сборки.
Облачный цикл базовой схемы выполнен в режиме `cached`. Исправление метаданных
дешборда проверено локально; его отображение на новой ВМ требует отдельной
проверки. Получение выпуска по публичным HTTPS-ссылкам проверяется отдельно.
S3 сохранён как отдельный способ разработки, без автоматической замены
GitHub Releases. [Режимы доставки и очистка артефактов](docs/artifacts.md).

## Дополнительные сценарии

```powershell
# Необязательная предварительная проверка без создания ресурсов
.\.tools\venv\Scripts\python.exe scripts/lab.py preflight

# Временный полный цикл: создаёт, проверяет и УДАЛЯЕТ свой тестовый стенд
.\.tools\venv\Scripts\python.exe scripts/lab.py test-cycle
```

`test-cycle` разрешён только без действующего стенда и незавершённых операций.
Он проверяет контрольные данные, повторный deploy и очистку в `finally`.
Обычные verify и test-cycle не добавляют es4 и не выключают ВМ.
[Явное добавление es4 и проверка отказоустойчивости](docs/optional-elasticsearch.md)
вынесены в отдельные эксплуатационные возможности развития проекта.

## Подтверждённые результаты и ограничения

[Полный облачный цикл текущего кода](docs/current-cloud-acceptance.json)
подтвердил четыре ВМ в ru-2 без Глобального роутера, три физических хоста ES,
кластер `green`, сайт, семь видов журналов, Kibana, повторный deploy и сохранность
данных. Удаление подтверждено state и API. [Таблица проверок и доказательства](docs/results.md).
[Локальный набор](docs/local-quality.md): 1636 тестов, Ruff, mypy win32/linux,
pre-commit и 100% измеряемых строк и ветвей.

App — единая точка отказа сайта, PostgreSQL и Kibana. HTTP не шифрует сессию
браузера. Реплика индексов и очередь Filebeat не гарантируют отсутствие потерь
при любой аварии. Межпуловый переход и намеренные обрывы SSH проверены локально;
последний облачный цикл их не испытывал. Дополнительные механизмы увеличивают
сложность сопровождения: [причины и границы повторного использования](docs/adr/0007-scope-and-reuse.md).
