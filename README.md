узлов. Filebeat собирает логи только серверов ДЗ07. Kibana доступна,

## Предварительная архитектура

Три отдельные ВМ Elasticsearch с ролями master/data/ingest, Filebeat только
на серверах ДЗ07, Kibana для Discover и dashboards. Сбор с серверов
предыдущих ДЗ не выполняется — они могут удаляться независимо.
Минимум одна реплика индексов; большинство 2/3 для выбора master.
Проверка отказоустойчивости должна включать потерю одного узла, запись
и поиск при отказе, восстановление узла и возврат green.

Выбран компактный учебный вариант, соответствующий текущим квотам:

| ВМ | Зона | Дополнительные сервисы | vCPU/RAM | Диск |
|---|---|---|---|---|
| es1 | Selectel ru-9a | Django/uWSGI + Nginx | 2 / 8 ГиБ | 20 ГиБ SSD |
| es2 | Selectel ru-9a | PostgreSQL 16 | 2 / 8 ГиБ | 40 ГиБ SSD |
| es3 | Selectel ru-9a | HAProxy + Kibana | 2 / 8 ГиБ | 20 ГиБ SSD |

Итого 6 vCPU, 24 ГиБ RAM, 80 ГиБ SSD и три floating IPv4.
Anti-affinity разводит ES-узлы по физическим хостам; одна зона не защищает
от отказа всего ЦОД. Вариант YC с тремя зонами сохранён в terraform/.
ES heap — 2 ГиБ на узел. Все компоненты Elastic Stack закреплены на 8.19.0;
deb-пакеты загружаются с официального сайта на рабочее место с проверкой
SHA512 и передаются на ВМ по SSH. На ВМ SHA512 проверяется повторно:
прямое скачивание на Selectel получило HTTP 403.
Это не рекомендация для промышленной нагрузки: сервисы конкурируют с ES
за ресурсы, небольшие диски ограничивают хранение.

HAProxy:80 → Nginx:8081 → uWSGI:8080 → PostgreSQL:5432. Сеть
Selectel 10.77.0.0/16, ES-адреса 10.77.1.10 / 10.77.2.10 / 10.77.3.10.
Транспорт ES:9300 и HTTPS API:9200
разрешены внутри группы безопасности; снаружи доступен HTTP портала и SSH:443
только с /32 оператора. Kibana слушает localhost:5601.
Для HTTP/transport ES включены TLS и проверка собственного CA; Filebeat
использует отдельную роль записи, Kibana — kibana_system. Пароли и CA key
остаются в .local; ключ CA на ВМ не передаётся.

`discovery.seed_hosts` содержит приватные адреса всех трёх ES-узлов.
`cluster.initial_master_nodes` задаётся только при первоначальном создании
кластера и удаляется после формирования; повторное включение при перезапуске
недопустимо. ES HTTP/transport не публикуются в интернет.

## Переиспользование предыдущих работ

- ДЗ01–ДЗ03: инфраструктурные подходы, Ansible и опыт сетевой связности.
- ДЗ04: Django/uWSGI, Nginx, исходные материалы портала, Terraform и проверка SSH.
- ДЗ05: подходы к preflight и независимому жизненному циклу стенда.
- ДЗ06: PostgreSQL / Patroni / HAProxy и проверки отказов.

README ДЗ06 подтверждает удаление его стенда. Наличие исходников и state
не означает наличия работающих серверов. Перед подключением агентов нужно
получить актуальный список ВМ и определить, какие источники восстановить.
В ДЗ07 источники воссоздаются на трёх новых ВМ из кода ДЗ04/ДЗ06; MySQL
ДЗ05 и HA-хранилище ДЗ04 не восстанавливаются, поскольку к сбору логов это
не требуется. Исторический SQL-дамп отсутствует: seed_lessons восстанавливает
четыре учебные статьи. Старые Terraform state и облачные стенды не изменяются.

## Развёртывание и проверки

Команды ниже для данного Windows-места. Зависимости перечислены в
requirements-local.txt; в независимом клоне установить их в отдельный venv,
обеспечить Terraform >=1.6,<2; путь можно задать через OTUS_TERRAFORM.
YC CLI требуется только для варианта YC; OTUS_YC и OTUS_YC_CONFIG позволяют
задать его путь и файл сессии. Для Selectel YC CLI не нужен.
Для Selectel используется terraform-provider-openstack/openstack 3.4.0 из ДЗ06.
Авторизация: OS_* либо OTUS_SELECTEL_AUTH — путь к локальному JSON оператора
из ДЗ05/ДЗ06. Секреты облака на ВМ не передаются.

```powershell
cd D:\Projects\Codex\OTUS\OTUS_DZ07
. .\scripts\env.ps1
.\scripts\save-operator.ps1
..\OTUS_DZ04\.tools\venv\Scripts\python.exe scripts/selectel.py prepare
..\OTUS_DZ04\.tools\venv\Scripts\python.exe scripts/cache_packages.py
..\OTUS_DZ04\.tools\venv\Scripts\python.exe scripts/selectel.py test
```

env.ps1 запрашивает данные интерактивно, пароль вводится скрыто.
save-operator.ps1 ограничивает ACL каталога .local текущим Windows-пользователем
и сохраняет operator.json, исключённый из Git. При наличии собственного
оператора передать env.ps1 параметр -UserName. Не отправлять пароль в чат.
Существующий пакетный кеш повторно используется после проверки SHA512.
По указанию пользователя operator.json сохраняется локально до согласования
документации и создания PR; в репозиторий файл не попадает.

prepare читает квоты, генерирует отдельные ключи, CA/сертификаты и пароли,
создаёт tfvars, выполняет init/validate. test проверяет свободные квоты
и create-only план, применяет его, конфигурирует ВМ через Paramiko,
проверяет сбор/визуализацию и отказ, затем всегда вызывает cleanup в finally.
Ключи SSH сверяются с console output, полученным по HTTPS API Nova; неизвестные ключи
не принимаются. При split VPN нужно добавить реальный исходящий SSH /32
в admin_cidrs до первого apply; определение IP по HTTPS может отличаться.
Ранее проверенные /32 из локальных параметров ДЗ05/ДЗ06 переиспользуются.

При частичном сбое сохранить state и журналы .local. configure повторяет
настройку существующих ВМ; deploy не заменяет и не удаляет существующие ВМ.
resume-test продолжает настройку существующего стенда, выполняет проверки
и всегда вызывает cleanup в finally; именно так возобновлялась передача пакетов.
После успешного формирования кластера bootstrap-настройка удаляется на всех
узлах без немедленного перезапуска; последующие перезапуски используют state.
В режиме test очистка выполняется и при ошибке. deploy — отдельная команда
для проверяющего, оставляющая стенд; она не использовалась как окончательный
режим этого задания. cleanup удаляет только ресурсы проверенного delete-only
плана собственного state. После сбоя процесса/питания finally не гарантируется:
восстановив доступ, выполнить scripts/selectel.py cleanup вручную.

Filebeat собирает journald на всех ВМ и файлы Nginx, PostgreSQL и HAProxy.
Также собираются собственные текстовые/JSON журналы Elasticsearch.
Общие deb-пакеты передаются на es1 один раз; es2/es3 получают их по приватному
HTTP:18080 и сверяют SHA512 с манифестом, переданным по SSH. Kibana передаётся
только на es3. Временный HTTP-сервис пакетов останавливается после установки.
Используется дисковая очередь до 512 МБ и три ES endpoint с load balancing.
Скрипт создаёт шаблон logs-otus-* (1 primary, 1 replica), ingest pipeline
классификации и разбора Nginx и ILM удаления через 7 дней.
Ежедневные индексы не используют rollover; возраст удаления считается от
создания индекса. Маленькие диски требуют контроля заполнения раньше 7 дней.

verify генерирует HTTP-запросы, SQL-запрос и journal-маркеры, затем требует
логи от трёх хостов и пяти service.name, разобранный HTTP status,
состояние green. docs/verification.json содержит фактические примеры.
failover выключает текущий ES master через Nova, проверяет SHUTOFF,
два оставшихся узла, нового master, запись/чтение, затем включает ВМ
в finally и ожидает три узла/green. Документы: docs/failover.json и recovery.json.
Время одного прогона включает API выключения и не является SLA/RTO.

## Kibana

Адрес es3 и остальные адреса доступны в Terraform output lab.
Открыть туннель, используя проверенный known_hosts и отдельный ключ ДЗ07:

```powershell
ssh -p 443 -i .local/otus_dz07 -o UserKnownHostsFile=.local/known_hosts -o StrictHostKeyChecking=yes -L 5601:127.0.0.1:5601 otus@<public-IP-es3>
```

Открыть http://localhost:5601, войти elastic с локальным паролем
из .local/secrets.json. Представление logs-otus-* использует @timestamp;
дашборд «OTUS DZ07 — журналы серверов» содержит сохранённую таблицу логов.
HTTP портала предназначен для чтения; вход в admin требует туннеля/HTTPS.
Потеря одной ВМ проверяет ES, но может одновременно прервать портал,
БД или Kibana: эти дополнительные сервисы не имеют собственных реплик.

## Проверка YC

Подробности и источники: [docs/yc-feasibility.md](docs/yc-feasibility.md).
CLI и конфигурация входа переиспользуются из ДЗ04; токены не копируются в ДЗ07.
После интерактивного входа выполнить из этой папки:

```powershell
..\OTUS_DZ04\.tools\venv\Scripts\python.exe scripts/yc_preflight.py
```

Команда только читает облака, каталоги и квоты. Результат сохраняется локально
в `.local/yc-preflight.json`; это не проверка доступной ёмкости через создание ВМ.
Результат сопоставления квот: docs/yc-quota-result.json. Квот достаточно,
но создание завершилось фактическими ошибками — docs/yc-deployment-attempt.json.
Удаление подтверждено в docs/yc-cleanup.json. Выбран Selectel.
