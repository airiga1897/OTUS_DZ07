# ДЗ07-ADR-0010. Глобальный роутер только для связи между пулами

**Статус:** однопуловый цикл подтверждён в ru-2; переход между пулами проверен локально.

## Причина и решение

ВМ одного пула взаимодействуют по общей приватной сети. Безусловное создание
Глобального роутера не требуется для этой связи и добавляет зависимость от
отдельного API и прав уровня аккаунта. Контроллер сохраняет последовательный
подбор ролей, порядок пулов и полную проверку квот. Результат поиска квот
включает пулы допустимого распределения оставшихся узлов. Если это один пул
и сохранённого роутера нет, API Глобального роутера не вызывается.

Перед созданием сети или ВМ во втором пуле повторно проверяются полное
сочетание, поддержка общей группы зон, доступ и квоты подключений. Неизвестный
ответ или отказ доступа блокирует переход. После создания ВМ во втором пуле
создаются роутер и подключения всех использованных сетей. Уже работающие ВМ,
сети и документы Elasticsearch не переносятся и не пересоздаются.

Каждый этап использует прежние журнал намерений, state, проверку владельца
и безопасного плана. Незавершённое подключение возобновляется через тот же
этап. Повторный deploy проверяет существующие ресурсы с запретом изменений;
он не создаёт новый роутер или дубликаты подключений. Сохранённый роутер
однопулового стенда автоматически не удаляется: его наличие является частью
действующей инфраструктуры и требует прежних прав для восстановления.

Начальная проверка нового test-cycle проверяет локальные данные и региональные
ресурсы. Проверка конфликта общего пространства имён выполняется перед созданием
Глобального роутера. Ресурсы без доказанной принадлежности новому запуску
не принимаются в его state и не удаляются его очисткой.

## Удаление и альтернативы

Destroy сохраняет порядок: ВМ, подключения, сети, роутер. Этапы отсутствующего
роутера не создаются ради удаления. Сохранённые, включая частично созданные,
общие этапы проверяются через API; ошибка сохраняет данные восстановления.
При полном журнале без общих этапов их API не нужен. При утрате журнала
расширенный поиск включает общие ресурсы и требует доступа к их API;
ошибку доступа нельзя заменить подтверждением очистки.

Безусловный роутер упрощает ветвление, но навязывает однопуловому стенду
необязательную услугу. Автоматическое удаление ранее созданного роутера
меняло бы действующую инфраструктуру при обычном deploy. Выбрано условное
создание с сохранением прежних этапов, ценой дополнительных проверок
перехода и восстановления. Предварительно сохранённые адресные резервы,
маршруты и правила своих подсетей не перерабатываются при повторном deploy.

## Подтверждения

Изолированные тесты проверяют однопуловый подбор без API роутера, ошибки
перехода во второй пул, сохранение ID, возобновление подключения и область
аудита. Они не подтверждают выделение ресурсов, работу маршрутов или
доставку данных между настоящими ВМ Selectel в разных пулах.

[Облачный test-cycle текущих исходников](../current-cloud-acceptance.json)
подтвердил размещение четырёх ВМ в ru-2 без создания Глобального роутера,
работу сайта, логов и Kibana, повторный deploy, сохранение данных и ID,
удаление со сверкой state/API. Использовался явно выбранный режим `cached`,
после завершения восстановлен `release`. Межпуловый переход, восстановление
прерванного подключения и удаление существующего роутера в этом прогоне
не испытывались; их подтверждение остаётся локальным.
