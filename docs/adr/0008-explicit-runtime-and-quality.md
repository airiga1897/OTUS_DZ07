# ДЗ07-ADR-0008. Явные зависимости контроллера и локальное качество

**Статус:** полный локальный набор проходит; базовый облачный цикл подтверждён в ru-2.

## Контекст

Передача целого модуля командной строки как зависимости связывает настройку,
SSH, служебные данные и облачные операции с неявным набором глобальных имён.
При выделении функций такие связи трудно проверить типами, а тесты могут
подменять уже не используемую функцию. Чтение конфигурации при импорте также
связывает тесты с исходным клоном вместо их временного рабочего каталога.

## Решение

`lab.py` разбирает команду и явно создаёт Runtime. Модули
`runtime_storage`, `runtime_ssh`, `runtime_infrastructure`,
`runtime_application` и `runtime_lifecycle` разделяют работу с файлами,
соединениями, инфраструктурой, службами и порядком команд. Узкие Protocol
описывают необходимые зависимости на границах; они не регистрируют провайдеров
и не создают универсальный механизм внедрения зависимостей.

В реализации Selectel подбор размещения, выполнение этапов и аудит удаления
выделены в `selectel_placement`, `selectel_stage_operations` и
`selectel_staged_audit`. Backend координирует этапы и сохраняет журнал.
Правила владения, допустимых планов, продолжения операции и удаления остаются
частью существующего жизненного цикла.

Общий перебор кандидатов использует небольшой Protocol с существующими
операциями этапа. Содержимое кандидата и формат идентификаторов определяет
адаптер; общий код не разбирает облачные поля и не преобразует их по догадке.
Тестовая подмена ограничена этим контрактом через `spec_set`, поэтому
обращение к несуществующему методу не создаёт молча новый Mock.

Runtime получает проверенную несекретную схему Selectel своего клона при
создании. Выбор полей для скрытия секретов не читает размещение или контекст.
Преобразование реквизитов в окружение Terraform использует эту же схему и
сохранённый регион. Значения реквизитов Python получает только из окружения;
чтение файла разработки остаётся явным действием PowerShell.

Передача файлов и полная настройка сервера имеют отдельные контракты.
Контракт настройки явно перечисляет необходимые действия SSH, доставки,
проверки размещения и подтверждения маршрута; он не получает весь модуль CLI.
Манифест доставки и результаты проверки артефактов имеют общие типы данных,
а GitHub Releases и необязательный S3 сохраняют отдельные способы авторизации.
Неизвестные формы внешних данных не становятся подтверждением принадлежности
ресурса, приватности объекта или успешной очистки. Сбой сохранения диагностики
не заменяет первоначальную ошибку инфраструктуры.

Журнал этапов имеет отдельную модель `StageJournal`: чтение проверяет форму
известных полей до использования Backend. Частичная стадия не обязана содержать
полный результат создания. Прежние nullable-поля и топология PostgreSQL
сохраняются для восстановления и удаления, без запуска снятых с поддержки ролей.
Корневой `null` журнала считается повреждением, а не отсутствием стенда.
Проверка формы не заменяет проверку проекта, владения и фактических ресурсов.
Завершённый выход Terraform проверяется отдельно; описание узла для приложения
требует полного набора полей, даже если журнал хранит незавершённую стадию.
Чтение Terraform state проверяет используемые поля и сохраняет неизвестные
данные провайдера. Повреждение коллекций, индексов или типов идентификаторов
не превращается в пустой state; исходный файл остаётся доступен для восстановления.

Подготовка Ansible получает настройки явным вызовом, без чтения JSON при
импорте. Настройки Django продолжают загружаться установленным Django способом.
Изменение импортов серверных сценариев требует проверки их отдельного запуска:
они не должны зависеть от пакетов локального контроллера.

Локальный набор — Ruff и mypy, unittest и pytest, Django factory_boy и Coverage.
Ruff объединяет форматирование, проверку импортов и выбранные правила качества.
Отдельные Black, isort и flake8 дублировали бы эти проверки; Poetry для изменения
способа установки зависимостей не требуется. Зависимости закреплены в файле
требований и устанавливаются в собственное окружение Python 3.12.
Локальный pre-commit вызывает те же инструменты; GitHub Actions не добавляется.

Запрос и ответ операции Ansible имеют общий типизированный контракт для
контроллера и исполнителя. Сохранённый JSON проверяется до использования:
повреждённый запрос блокирует продолжение, повреждённый результат не становится
успехом или разрешением повторного запуска. Необязательные данные прогресса
остаются отдельными от результата операции.

Строгий mypy выполняется для Windows и Linux по всей области исходников.
Проверка только Windows ошибочно оценивала бы системные API Linux;
проверка только Linux оставила бы без проверки ветви блокировки Windows.
Исполнитель на app явно отклоняет собственные Linux-операции на Windows.
Локальные тесты подставляют системные вызовы и проверяют оба пути; они
не подтверждают выполнение systemd или сигналов на настоящей ВМ.

Тесты границ используют настоящий Runtime при подготовке входных параметров
Terraform. Предоставление тестовой обвязкой дополнительных модулей не считается
подтверждением того, что такие зависимости доступны пользовательской команде.

## Альтернативы и последствия

Сохранить весь код в `lab.py` проще по числу файлов, но это оставляет
неявные зависимости и усложняет независимую проверку операций. Большой общий
интерфейс с любыми атрибутами лишь переименовал бы эту связь. Отдельный внешний
контейнер зависимостей добавил бы механизм, который этому проекту не нужен.

Цена разделения — больше модулей и явных контрактов, а также необходимость
обновить тестовые точки подмены на реальные границы внешних операций.
Извлечение функции само по себе не подтверждает правильность контракта.
Необходимы проверки форм данных, ошибок и восстановления, а не только процента
покрытия. Рабочий код не исключается из анализа для достижения показателя.

Полный набор запускается через `scripts/check.py`. Результат считается готовым
только после успешных тестов, 100% измеряемых строк и ветвей, чистых Ruff и mypy
и повторного успешного запуска. Локальный результат приведён в инструкции проверок.
Облачные отчёты прежнего выпуска не подтверждают этот рефакторинг.
