# ДЗ07-ADR-0006: область удаления и восстановления

Статус: удаление сохранённого стенда проверено в ru-2; потеря контекста и
ошибки API проверены локально.

## Причина

Обход всех пулов при наличии журнала стенда избыточен. Технический пул
авторизации общего Глобального роутера также не означает размещения там
региональных ресурсов. При потере журнала ограничение текущими предпочтениями,
напротив, может скрыть остатки предыдущей попытки.

## Решение

`destroy` проверяет привязку контекста и state, затем подтверждает остановку
Ansible. Удаление идёт от зависимых ресурсов к общим: ВМ, подключения
Глобального роутера, региональные сети, общий роутер. Родитель не удаляется,
пока удаление дочерних ресурсов не подтверждено через state и API.

Область итогового регионального аудита — объединение пулов сохранённых этапов,
включая незавершённые попытки. Технический пул стадии `global` отдельного
регионального обхода не требует; общие ресурсы проверяются через API
Глобального роутера. Изменение `.env` не меняет область удаления.
Проверяются ВМ, диски, порты, сети, подсети, маршрутизаторы, группы безопасности,
их правила, группы серверов и публичные IP. Повторные чтения одинаковых
региональных коллекций в итоговом аудите устранены.

До создания этапа атомарно сохраняются намерение операции, пул, виды ресурсов,
проект и признаки принадлежности: namespace, владелец и префикс имени.
API может создать объект раньше записи ID в Terraform state. Такой объект
проверяется и при пустом state попытки. Совпадение признаков без сохранённого
ID блокирует автоматическое удаление: требуется явное восстановление,
а не удаление или импорт по одному имени.

Без достаточных данных восстановления запускается явно обозначенный расширенный
поиск по пространству имён текущего проекта во всех обнаруженных пулах с API
compute, volume или network, включая исключённые из нового размещения.
Если API нужного типа ресурсов недоступен в обнаруженном пуле, поиск считается
неполным, кроме явно согласованных исключений области аудита ниже:
отсутствие endpoint само по себе не выдаётся за отсутствие ресурсов.
Глобальный роутер проверяется отдельно. Каталог endpoint задаёт область чтений
и не доказывает отсутствие ресурсов. При утрате обязательного журнала этапов
поиск остаётся только читающим, данные восстановления сохраняются.
Выделенный проект не разрешает удаление чужих ресурсов.

### Явные исключения сервисов Selectel

В `config/cloud.json`, `audit.service_exclusions`, сетевые диски (`volumev3`)
исключены из расширенного аудита пустого локального стенда в ru-4 и ru-5.
Это согласованная граница проверки адаптера, а не утверждение об отсутствии
дисков у провайдера. Читающая проверка каталога проекта не нашла в этих пулах
`volume`, `volumev2` и `volumev3`. Развёртывание проекта в этих пулах исключено
настройками размещения; подбор также требует дисковый API.

ВМ, сети, публичные IP и общие ресурсы продолжают проверяться. Если `volumev3`
опубликован, он проверяется даже в указанном пуле: ошибки доступа и сети не
игнорируются. В отчёте сохраняется `service_exclusions`, а
`audit_complete_within_policy` означает завершение проверки согласованной
области, не проверку исключённых дисков.

Исключения не применяются к сохранённой области стенда или принудительному
поиску при повреждении данных восстановления. Непустой state требует штатного
пути удаления сохранённых ресурсов; наличие в нём диска нельзя обойти этим
исключением. Остальные отсутствующие API по-прежнему означают неполный аудит.
Альтернатива — требовать недоступный API во всех пулах — блокировала повторный
destroy уже удалённого стенда. Общее правило пропуска любого отсутствующего
API отвергнуто: оно могло бы скрыть непроверенные остатки. Цена выбранного
решения — явная ограниченная область и необходимость пересмотра политики,
если проект начнёт использовать диски в этих пулах.

Полный пригодный для задачи общий каталог ресурсов не подтверждён.
[API облачных проектов и ресурсов](https://docs.selectel.ru/api/cloud-projects-and-resources/)
не заменяет проверки всех нужных типов OpenStack. Проверенный читающий запрос
общего списка floating IP вернул `403`: это ограничение доступа, а не отсутствие
ресурсов или возможности. Обезличенный результат —
[global-inventory-api-discovery.json](../global-inventory-api-discovery.json).

Независимые региональные и общие чтения выполняются с ограничением
`audit.read_workers` в `config/cloud.json`. Ошибка любого чтения означает
неполный аудит. Остальные независимые чтения завершаются; исходная ошибка
сохраняется. Контекст, state и ключи удаляются только после полного успешного
подтверждения очистки. Реквизиты разработки сохраняются.

## Проверка и ограничения

Изолированные тесты проверяют область сохранённого стенда и попытки, утрату
контекста, объект без ID в state, ошибки API и сохранение исходной ошибки.
Они не подтверждают облачную работоспособность изменений.

Сообщения INFO перед действием и после него показывают этап, пул и длительность.
WARNING обозначает расширенный поиск. Время аудита зависит от числа сохранённых
пулов, страниц API и повторов сетевых чтений; фиксированная длительность не
гарантируется. DEBUG SDK автоматически не включается.
