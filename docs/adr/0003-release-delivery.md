# ДЗ07-ADR-0003. Доставка при развёртывании через GitHub Releases

**Статус:** опубликованный выпуск проверен; текущие исходники испытаны с cached
и требуют отдельного согласованного Release.

## Контекст

Проект должен развёртываться из чистого клона без доступа к приватному S3
разработки. ВМ должны получать исходники и пакеты
по HTTPS с проверкой закреплённых SHA512. Единые команды управления сохраняются.

## Решение

Использовать режим `release` для основного развёртывания и сохранить S3
как отдельный режим разработки.
Сборщик выпуска работает с точным коммитом чистого дерева и проверенными
пакетами Elastic. Он создаёт архив для ВМ, пакеты, манифест, настройки выпуска
и SHA512SUMS в локальном каталоге, без публикации и облачных операций.

После публикации несекретные настройки репозитория закрепляют версию,
коммит, SHA512 и размер манифеста. Контроллер проверяет его и передаёт ВМ
общий формат ссылок, хешей и размеров. Загрузчик ВМ проверяет HTTPS, размер,
SHA512 и безопасность распаковки; настройка служб остаётся в Ansible.
Ключи и API S3 в режиме `release` не требуются. Ошибка выпуска не включает
автоматический переход на S3 или передачу локального кода по SSH.

## Границы коннекторов

[`release_artifacts.py`](../../scripts/release_artifacts.py) и
[`s3_artifacts.py`](../../scripts/s3_artifacts.py) — отдельные коннекторы с общей
операцией `prepare(root)`. Выбор в [`delivery.py`](../../scripts/delivery.py) явный; ошибка коннектора
не переключает источник. Проверки целостности и снимок кода вынесены в
[`artifact_content.py`](../../scripts/artifact_content.py), чтобы Release и общий транспорт не зависели от S3.
S3 подключается при явном выборе этого режима либо обработке его собственных
служебных маркеров. В конфигурации нет обязательного бакета разработки.

S3 нужен для закрытой доставки неопубликованных версий и повторного
использования крупных проверенных пакетов в разработке. Для основного
развёртывания используется закреплённый GitHub Release.
Разделение коннекторов проверяется локально с запретом импорта S3 SDK
в процессе Release; новый облачный прогон для этих изменений не выполняется.

Коммит настройки выпуска может следовать за коммитом исходников, чтобы
хеш архива не зависел от манифеста, содержащего этот хеш. Выбранный источник
явно обозначает версию кода: для неопубликованных изменений разработки можно
явно выбрать S3, опубликованный выпуск доставляется через Releases.

Привязка выполняется локальной командой `release_artifacts.py configure`:
проверяются размеры и SHA512 манифеста и файлов, точное совпадение исходного
коммита, чистота дерева и отсутствие локальных признаков стенда. Она записывает только два файла
конфигурации, без публикации, сетевых запросов и ручного переноса JSON.
Первый коммит содержит исходники, второй закрепляет выпуск в конфигурации.
Release привязан к первому коммиту. Для развёртывания доступны оба коммита.

## Последствия

Из чистого клона проверены сборка и доставка через подставной HTTPS с
синтетическими пакетами, отклонение повреждённых файлов, чужой версии и
незакоммиченного дерева. Подготовка чистого клона и получение публичного
манифеста подтверждены [отдельной проверкой](../release-public-verification.json).
[Облачный прогон](../release-cloud-acceptance.json) подтвердил получение файлов ВМ,
сайт, журналы, Kibana, повторный deploy и удаление обоих тестовых стендов.
В конфигурации по умолчанию выбран закреплённый опубликованный выпуск.
Проверка полного снимка текущего проекта исполняется в отдельном процессе:
получение всех файлов, распаковка и inventory проверяются без сети и вызовов S3.
Исходный репозиторий и его HEAD не изменяются.
