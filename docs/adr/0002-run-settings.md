# ДЗ07-ADR-0002. Настройки запуска в .env и обнаружение пулов

**Статус:** Принято для ДЗ07.

## Контекст

Каталоги проверяются по одному пулу в установленном порядке, до получения
полного совместимого сочетания для оставшихся ролей. Отложенные пулы читаются
при необходимости продолжения подбора. Успешные ответы неизменяемых каталогов
повторно используются только внутри запуска; квоты и состояние ресурсов
не кэшируются. Перед выбором проверяются и все сохранённые действующие пулы.
Резервы CIDR для разрешённой области фиксируются до первого создания сети,
чтобы последующий переход к кандидату не менял действующие сетевые правила.
Резерв CIDR не означает создания ресурсов или подтверждённой совместимости.
Этот порядок проверен локально; его облачное испытание не выполнено.

Удаление использует сохранённые этапы и попытки, а не весь список резервов
или новые предпочтения: [ADR-0006](0006-destroy-audit-scope.md).

Параметры конкретного запуска должны быть доступны в корне клона без правки
кода. Закрытый список пулов может скрывать доступное совместимое размещение.
При этом изменение предпочтений не должно переносить действующие ресурсы.

## Решение

Значения по умолчанию хранить в `.env.example`, локальные переопределения —
в исключённом из Git `.env`. Единый загрузчик проверяет буквальные значения;
переменные сессии имеют последний приоритет. Реквизиты доступа остаются
в прежней отдельной схеме PowerShell и поступают Python/Terraform из окружения.
В JSON не дублируются параметры запуска.

Адаптер Selectel обнаруживает пулы через API. Предпочтения задают порядок,
исключения запрещают использование. Совместимость проверяется для полного
сочетания ресурсов и группы зон. Ошибка или неизвестный ответ API не означают
отсутствие поддержки. Алгоритм обнаружения и перебора принадлежит провайдеру;
общий контроллер управляет этапами и сохранением ресурсов.

Разрешённые семейства ВМ задаются масками `SELECTEL_FLAVOR_NAME_PATTERNS`,
без уменьшения vCPU/RAM профиля и без перехода на локальный загрузочный диск.
Для зоны сохраняются все совместимые сочетания конфигурации и диска,
включая разрешённый AMD и SSD. Выбор только первого совпадения скрывал бы
допустимые альтернативы при нехватке физических хостов. Наличие сочетания
в каталоге подтверждает совместимость, но не текущую ёмкость планировщика.
Повторный deploy использует сохранённые ID и параметры работающих узлов;
новые предпочтения не разрешают их пересоздание.

Размещение, подсети и существенные параметры сохраняются в контексте.
Изменение `.env` не разрешает замену ВМ, смену режима разнесения или расширение
сетевого графа действующего стенда. Удаление использует сохранённую область
и настройки независимо от текущих предпочтений.

Диагностический `REQUIRE_DISTINCT_HOSTS=false` убирает `scheduler_hints`
у ES и явно отмечается в проверках. По умолчанию разнесение обязательно.
Диагностический результат не доказывает защиту от потери физического хоста.

## Причины и последствия

Пользователь меняет настройки без редактирования исходников. Один загрузчик
устраняет разные правила приоритета в PowerShell, Python и Terraform.
Обнаружение через API позволяет проверить альтернативные пулы, сохраняя
явные ограничения сети, образов и дисков. Снимок настроек предотвращает
неявное пересоздание ресурсов после правки локального файла.

Названия вычислительных сегментов не приравниваются к сетевым доменам:
внутри пула Selectel сеть охватывает несколько сегментов. Адаптер выбирает
точный домен API либо единственный обычный домен того же пула; неоднозначность
требует явного соответствия. Выбор типа диска и контрольной суммы образа
от этого не расширяется. [Каталоговая проверка](../pool-catalog-audit.md).

Новые настройки и порядок создания требуют отдельного облачного испытания;
mock-тесты не подтверждают фактическую доступность хостов и межпуловую связность.

Для образа `Ubuntu 24.04 LTS 64-bit` используется явный список разрешённых
значений Glance `checksum` в `config/placement.json`, поле `image_checksums`.
Это MD5, а не SHA. Список включает текущую сборку и сборку ru-2;
он не дублируется в `.env`, коде или Terraform. Точное название, состояние
`active`, публичность, `os_distro=ubuntu`, архитектура и ограничения ресурсов
проверяются независимо от MD5. Отсутствующий, пустой или некорректный список
блокирует подбор, совпадения одного названия недостаточно.

ru-4 и ru-5 исключены в настройках запуска: точного требуемого образа
в проверенных каталогах нет. Прежние исключения сохраняются.
Каталоговый допуск сборки ru-2 не подтверждает запуск ролей на ней;
это отдельно подтверждено [полным test-cycle ru-2a](../ru2-test-cycle-summary.json). Изменение списка образов
не переносит действующие ресурсы и не меняет сохранённые ID ВМ и образов.

[Параметры и эксплуатация](../run-settings.md).

Порядок по умолчанию — ru-2 → ru-9 → ru-3: ru-2a подтверждён полным
test-cycle, остальные два пула сохраняются как предпочтительные альтернативы.
ru-6 исключён из-за отсутствия разрешённых типов дисков, а ru-1b — через
`SELECTEL_EXCLUDED_SEGMENTS` из-за отсутствия диска с подтверждённой привязкой.
Списки хранятся в `.env.example` и переопределяются в `.env`.
Временный недостаток квот проверяется динамически; он не служит основанием
постоянно исключать ru-1a или ru-2b. Изменение предпочтений и исключений
не разрешает переносить действующий стенд или менять сохранённые ID.
