# ДЗ07-ADR-0005. Явные эксплуатационные сценарии ES

**Статус:** Реализовано и проверено локально; облачное испытание отдельно.

## Решение

Сохранить обязательную схему app + es1–es3 и обычные verify/test-cycle
без отключений и расширения. Повторно используемые механизмы предыдущих
учебных проектов развивать отдельно как дополнительные эксплуатационные
возможности: `verify --es-failover` и `add-es4`.

Проверка отказоустойчивости выбирает master из собственного кластера и
получает пул из сохранённой привязки узла. До выключения сохраняется маркер;
восстановление выполняется при любом результате проверки. Если связь утрачена,
успех не объявляется, маркер остаётся для продолжения без нового выключения.
Первоначальная ошибка сохраняется при ошибках завершающих действий.

Запрос es4 сохраняется атомарно в контексте того же стенда. Базовая конфигурация
не переписывается; обычный deploy учитывает ранее явно запрошенное расширение.
es4 — data/ingest без изменения первоначального состава master-eligible узлов.
Существующие планы, ID, данные и маркер загрузки фикстуры сохраняют защиту.
Удаление и замена действующих ресурсов не становятся разрешёнными операциями.

## Последствия

Сценарии используют существующие адаптер Selectel, Terraform и Ansible,
без нового общего фреймворка. Повторное добавление и продолжение после ошибки
не создают новый es4. Незавершённое восстановление блокирует настройку и
расширение, а destroy сохраняет существующий аудит удаления своих ресурсов.
Локальные mock-проверки не заменяют отдельное испытание в облаке.
