# Доставка через GitHub Releases

Для сдачи используется явный режим `release` в `config/services.json`.
Режим `s3` остаётся отдельным вариантом разработки. Автоматической замены
источника при ошибке нет. В конфигурации закреплён опубликованный
[выпуск v1.0.0](https://github.com/airiga1897/OTUS_DZ07/releases/tag/v1.0.0).
[Проверка чистого клона](release-public-verification.json) и
[облачный прогон](release-cloud-acceptance.json) подтверждают путь без S3.

## Подготовка выпуска

Код, Terraform, Ansible, документация и закреплённые SHA512 пакетов находятся
в репозитории. Перед сборкой необходимо согласовать изменения и сохранить
проверенную версию коммитом. Незакоммиченные и неотслеживаемые изменения
блокируют сборку. Служебные каталоги исключены из Git.

```powershell
# Выполняется сопровождающим из чистого рабочего дерева
# v1.0.0 — пример явно выбранной версии
.\.tools\venv\Scripts\python.exe scripts/release_artifacts.py build --tag v1.0.0

# Проверить все файлы и закрепить выпуск в конфигурации текущего клона
.\.tools\venv\Scripts\python.exe scripts/release_artifacts.py configure --assets .tools/releases/v1.0.0
```

Команда проверяет три пакета в `.tools/elastic-packages` по
`config/elastic-artifacts.json`, получает исходники через `git archive` точного
коммита и создаёт `.tools/releases/v1.0.0`. Номер версии выбирается явно;
существующий каталог не перезаписывается. Каталог появляется только после
успешной сборки и повторной проверки состояния репозитория.

| Файл | Назначение |
| --- | --- |
| `source.tar.gz` | Код и конфигурация для ВМ из закреплённого коммита, без служебных данных |
| Три `.deb` | Elasticsearch, Filebeat и Kibana версии из конфигурации с официальными закреплёнными SHA512 |
| `manifest.json` | Коммит, точная версия, HTTPS-ссылки, размеры и SHA512 файлов |
| `release-settings.json` | Несекретная привязка к выпуску и SHA512/размер манифеста |
| `SHA512SUMS` | Контрольные суммы всех перечисленных файлов |

Архив для ВМ содержит `app`, `scripts`, `config`, `ansible`,
`terraform-selectel` и необходимые корневые файлы. Полная документация и
локальные тесты доступны в клоне. Проверка содержимого запрещает state,
реквизиты, приватные ключи, `.env`, media, ссылки и небезопасные пути.
Файлы из `.local` и `.tools` в архив не попадают.

После отдельного разрешения публикации выпуск с выбранным тегом связывается
с коммитом из манифеста, а перечисленные файлы загружаются в него.
Команда `configure` выполняет второй локальный этап: проверяет SHA512 и размеры
всех файлов, совпадение исходного коммита с HEAD и отсутствие локальных state
и контекста стенда, затем записывает `github_release` в `config/artifacts.json` и переключает
`artifact_delivery` в `config/services.json` на `release`. Она требует чистого
рабочего дерева и каталога файлов внутри этого клона; сеть и S3 не использует.
Настройки записываются без BOM, вручную переносить JSON не требуется.

Полученные изменения двух файлов сохраняются отдельным коммитом настройки
проверяющего после локальных проверок и согласования. Тег Release указывает
на первый, исходный коммит; ветка `elkcluster` для проверяющего содержит
также второй коммит с готовой привязкой. Это устраняет циклическую зависимость хеша архива
от манифеста, который описывает этот архив. Произвольные заполнители не
считаются готовым выпуском. Файлы опубликованной версии не подменяются.

Сборщик не создаёт тег, не делает push и не публикует Release. Пустые или
неполные настройки выпуска останавливают deploy до создания ВМ.
Команда `configure` также не создаёт коммит и ничего не публикует.
До отдельного разрешения публикации эти действия выполняются только локально.

## Запуск проверяющим

После публикации репозитория с настроенным режимом `release`:
клонируется ветка `elkcluster` с коммитом привязки, а не тег исходного архива.

```powershell
git clone --branch elkcluster https://github.com/airiga1897/OTUS_DZ07.git
Set-Location OTUS_DZ07
.\scripts\setup.ps1

# Собственные реквизиты Selectel только в окружении текущей сессии
. .\scripts\env.ps1

# Развернуть и оставить стенд работающим
.\.tools\venv\Scripts\python.exe scripts/lab.py deploy

# Проверить сайт, Elasticsearch, источники логов и Kibana
.\.tools\venv\Scripts\python.exe scripts/lab.py verify

# Вывести размещение и ссылки для просмотра
.\.tools\venv\Scripts\python.exe scripts/lab.py open

# Удалить и подтвердить отсутствие ресурсов
.\.tools\venv\Scripts\python.exe scripts/lab.py destroy
```

Настройки размещения задаются в `.env` по основной инструкции README.
Для этого сценария не нужны ключи S3 и команда `env.ps1 -Artifacts`.
Облачные реквизиты не включаются в выпуск и вводятся скрыто через PowerShell.
В корне чистого клона нет `.local`, `.tools`, `.env`, SSH-ключей и state:
подготовка создаёт собственное окружение, а deploy — собственные служебные файлы.

При необходимости доступность закреплённого манифеста можно проверить после
setup до любых облачных команд:

```powershell
.\.tools\venv\Scripts\python.exe scripts/release_artifacts.py prepare
```

Команда обращается только к HTTPS выпуска и создаёт локальный манифест доставки.
Она не создаёт облачных ресурсов и не требует реквизитов Selectel или S3.

Контроллер проверяет SHA512 манифеста по закреплённым настройкам репозитория,
его коммит, версию, перечень пакетов, ссылки и хеши. ВМ сама скачивает файлы
по HTTPS; перенаправления допускаются только на HTTPS. После проверки размера
и SHA512 архив распаковывается существующим безопасным загрузчиком, пакеты
устанавливаются ролями Ansible. Исходники конкретного выпуска не заменяются
локальными незакоммиченными изменениями. Для разработки текущего кода
используется явный режим S3.

Локальная проверка [текущего проекта](../scripts/test_release_current_clone.py)
копирует актуальные исходники в изолированный репозиторий, создаёт коммит
исходников и коммит привязки, затем настоящий чистый клон проверяющего.
В отдельном Python-процессе проверяются подготовка доставки, загрузка исходников
и всех трёх пакетов, распаковка, наличие ролей, фикстуры и Terraform lock-файлов
в клоне, формирование inventory для четырёх ВМ. Синтетические пакеты и подставной
HTTPS позволяют выполнять проверку без сети, реквизитов и вызовов S3.
Эти временные коммиты не изменяют основной репозиторий и не являются выпуском.
Фактическое получение файлов облачными ВМ подтверждено отдельно:
[обычный verify и полный test-cycle с очисткой](release-cloud-acceptance.json).
