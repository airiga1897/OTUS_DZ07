# Подготовка и управление стендом

## Подготовка

Все команды выполняются локально в PowerShell на Windows из корня клона ДЗ07.
Проверенное окружение: Python 3.12 и Terraform 1.16.3 на Windows с PowerShell.
Нужны Python >=3.11, Terraform >=1.6,<2, OpenSSH и доступ к API Selectel,
официальным пакетам Elastic и SSH серверов. Квоты: три ВМ, 6 vCPU, 24 ГиБ RAM,
80 ГиБ SSD, три публичных IPv4, сеть, подсеть, маршрутизатор, группа безопасности
и группа серверов с anti-affinity. Для кеша пакетов нужно не менее 3 ГиБ свободного места.

В панели Selectel самостоятельно создаются проект и сервисный пользователь
с ролью `member` в выбранном проекте (управление облачными серверами,
дисками и сетями); не требуется доступ к другим проектам или управлению аккаунтом.
Там же доступны номер аккаунта, ID проекта и данные сервисного пользователя.
Программные проверки имён и Terraform-плана дополняют облачные права;
они не ограничивают права самой учётной записи.

Однократная подготовка окружения; после неё установить Terraform по инструкции ниже:

```powershell
python -m venv .tools/venv
.\.tools\venv\Scripts\python.exe -m pip install -r requirements-local.txt
```

По умолчанию используется `.tools/terraform.exe` этого проекта.
Другой путь задаётся через `OTUS_TERRAFORM` в каждой новой сессии PowerShell. Версия поставщика OpenStack
закреплена в lock-файле; [зеркало](../terraform-selectel.rc) применяется автоматически.

## Реквизиты в окружении PowerShell

Основной сценарий для проверяющего:

```powershell
. .\scripts\env.ps1
```

Скрипт последовательно запрашивает номер аккаунта, ID проекта, имя оператора
и пароль. Пароль вводится скрыто. Вводить значения в командную строку,
редактировать код или создавать JSON с реквизитами не требуется.
Данные доступны только дочерним процессам текущей сессии PowerShell;
после закрытия окна их нужно ввести заново. deploy, verify и destroy
используют то же окружение.

[Несекретная настройка](../config/selectel.json) — единственное место определения
перечня полей, имён переменных окружения и подсказок ввода. Регион, зона,
правила выбора образа и flavor находятся там же. Реальных значений реквизитов
в файле нет. [Модуль credentials](../scripts/credentials.py) единолично выбирает,
читает и проверяет источник; API и Terraform получают готовую конфигурацию.
Неполное окружение считается ошибкой. Автоматического переключения на файл нет.

Ключи, сертификаты, пароли сервисов, параметры образа и flavor создаются
автоматически. Адрес /32 определяется через HTTPS. При VPN нужный исходящий SSH
/32 следует заранее добавить в `admin_cidrs` локального
`terraform-selectel/terraform.tfvars.json`, например `{"admin_cidrs":["<IPv4>/32"]}`.
SSH-ключи ВМ сверяются с console output через HTTPS API Nova.
Секреты облака на ВМ не передаются.

SSH использует TCP/22. Портал доступен по HTTP/80, Kibana — по HTTP/5601
без туннеля. Для SSH и Kibana разрешены только /32 из `admin_cidrs`.
После смены интернет-маршрута проверить фактический исходящий IPv4 и обновить
разрешённые адреса. Наличие старого /32 не разрешает доступ с нового адреса.
Пароль Kibana и логи передаются по HTTP без шифрования; режим предназначен
для временного учебного стенда. Elasticsearch остаётся в приватной сети с TLS.

## Развернуть

Создаёт платные ресурсы и оставляет сервисы работающими:

```powershell
.\.tools\venv\Scripts\python.exe scripts/lab.py deploy
```

Проверяются квоты, готовятся параметры, выполняются Terraform init/validate,
загрузка пакетов с проверкой SHA512, создание ВМ и настройка сервисов.
Завершающая проверка подтверждает поступление журналов. Пакеты из локального
кеша используются повторно после проверки хеша. Общие пакеты передаются на es1
по SSH, далее по приватной сети с повторной проверкой SHA512; временный HTTP-сервис
останавливается. План разрешает только создание и отсутствие изменений.

## Проверить

Команда намеренно выключает ВМ текущего master Elasticsearch:

```powershell
.\.tools\venv\Scripts\python.exe scripts/lab.py verify
```

Проверяются HTTP через балансировщик, события трёх серверов и пяти источников,
разбор HTTP status и green. Затем проверяются SHUTOFF ВМ, новый master,
сохранность прежнего документа, запись и чтение при двух узлах.
ВМ включается в finally; ожидаются три узла и green, повторно проверяются
приложение и поступление логов. При успехе стенд продолжает работать.
Отчёты обновляются в [docs/](./).
Дополнительно с управляющего компьютера проверяется страница входа Kibana
на HTTP/5601. Пароль при этой автоматической проверке не отправляется.
Результат сохраняется в `docs/kibana-public.json`; файл появляется после
успешной проверки внешнего доступа на развёрнутом стенде.

## Удалить

Разрушающая операция: удаляет ресурсы и данные текущего стенда.

```powershell
.\.tools\venv\Scripts\python.exe scripts/lab.py destroy
```

Используется собственный state и план только на удаление. Проверяются пустой
state и отсутствие ресурсов ДЗ07 через API, включая сохранённые перед удалением
ID публичных IP. Результат — [отчёт очистки](selectel-cleanup.json).
State, контекст, ключи и необходимые секреты приложения остаются локальными.
Сохранение этих служебных файлов не означает сохранение реквизитов оператора.

При ошибке создания/настройки или проверки выполняются диагностика и удаление.
Ошибка подготовки до создания ресурсов сохраняет существующий стенд.
При остановке процесса или потере питания finally не гарантируется:
после восстановления доступа выполнить `destroy` вручную. Не удалять state
и `.local` до подтверждённой очистки.

## Установка Terraform

Скачать Windows amd64 архив Terraform с [официальной страницы](https://developer.hashicorp.com/terraform/install),
сверить SHA256 по опубликованным суммам и распаковать `terraform.exe` в `.tools/`.
Если Terraform уже установлен в PATH, вместо копирования использовать:

```powershell
$env:OTUS_TERRAFORM = (Get-Command terraform.exe).Source
```

## Результат команд

| Команда | Ожидаемый результат |
| --- | --- |
| `deploy` | `APPLICATION READY`, работающие сервисы, адреса в `.local/lab.json` |
| `verify` | `LIVE VERIFICATION PASSED`, восстановлены три узла и green |
| `destroy` | `DESTROY CONFIRMED`, пустой state и успешный API-аудит |

Если Selectel возвращает `No valid host was found`, свободных квот недостаточно
для подтверждения доступной ёмкости физических хостов. Дождаться подтверждения
очистки, сохранить state/контекст и повторить развёртывание после появления
ёмкости. Состояние `ERROR` не означает готовность ВМ или приложения.

При ошибке внешней команды PowerShell следует проверить `$LASTEXITCODE`.
Успешная остановка ВМ не прекращает расходы на диски и IP; команда `destroy`
удаляет и эти ресурсы. Повторный `deploy` не заменяет существующие ресурсы;
для нового независимого стенда сначала завершить `destroy`.

Доступные роли Selectel описаны в [справочнике ролей](https://docs.selectel.ru/access-control/role-reference/).

## Служебные файлы и привязка к проекту

| Локальный путь | Содержимое |
| --- | --- |
| `terraform-selectel/terraform.tfstate` | Технические ID созданных ресурсов, состояние Terraform |
| `.local/selectel-context.json` | ID проекта и регион как привязка стенда |
| `.local/lab.json` | Адреса и ID ВМ для подключения |
| `.local/otus_dz07`, `.local/known_hosts` | Ключ SSH и проверенные ключи серверов |
| `.local/secrets.json`, `.local/certs/` | Секреты приложения и материалы TLS |
| `.local/*log` | Диагностика с фильтрацией реквизитов |

ID проекта существует до развёртывания и вводится оператором; технические ID
ресурсов назначаются облаком. Контекст не хранит номер аккаунта, имя оператора
или пароль. Несовпадение проекта с контекстом блокирует работу до облачных
изменений. При переходе на другой проект использовать отдельный клон;
удалять старый контекст допустимо только после подтверждённого destroy.
При сбое удаления сохранять state, контекст и ключи. Реквизиты допускается
удалить из окружения и повторно ввести для следующей попытки очистки.

После завершения работы очистить окружение:

```powershell
. .\scripts\env.ps1 -Clear
```

## Локальный файл для разработки

Этот режим выбирается явно и не требуется проверяющему. После ввода через
`env.ps1` при необходимости сохранить реквизиты локально:

```powershell
.\scripts\save-operator.ps1
```

Скрипт ограничивает права каталога `.local` текущим пользователем Windows
и вызывает единый модуль реквизитов. Файл `.local/operator.json` исключён из Git;
его содержимое не выводится и не включается в примеры или доказательства.
В новой сессии разработки выбрать файл явно:

```powershell
$env:OTUS_SELECTEL_AUTH = Join-Path (Get-Location) '.local/operator.json'
```

При заполненных реквизитах в окружении они имеют приоритет. Неполное окружение
нужно очистить через `env.ps1 -Clear` и затем явно выбрать файл либо заново
ввести все данные. После завершения разработки и подтверждённой очистки ресурсов:

```powershell
Remove-Item -LiteralPath .\.local\operator.json
. .\scripts\env.ps1 -Clear
```

При ошибке destroy файл не удалять до необходимой очистки; в режиме без файла
сохранить служебные данные и повторно ввести реквизиты. Сырые отчёты и диагностика
не публикуются. Запись в `docs/*.json` фильтрует известные реквизиты, поля
авторизации, публичные IP и ID облачных ресурсов. Проверка API использует токены
только в памяти процесса; отладочные логи Terraform с реквизитами отключены.
