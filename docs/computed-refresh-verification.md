# Проверка обновления вычисляемых полей OpenStack

Защита повторного развёртывания проверяет две части Terraform-плана отдельно:
наблюдаемое изменение состояния (`resource_drift`) и запланированные операции
(`resource_changes`). Для существующих ресурсов операции должны быть `no-op`.

В сохранённой диагностике [защиты плана](terraform-faults/app-plan-guard-d6823a2d1ded4852a71ba2bc74a298de.json)
операции были `no-op`, но чтение OpenStack дополнило поля после создания и
привязки ресурсов: метаданные ВМ, привязку floating IP, владельца порта,
DNS, QoS и пустые теги. Прежний допуск знал только отдельные обновления,
включая привязку загрузочного диска, поэтому остановил повторный deploy.

В [адаптере проверки](../scripts/selectel_refresh.py) разрешены только
наблюдения, соответствующие сохранённым ID, владельцу, сети, подсети и адресу.
Поле `x_cloud_maintenance` допускается только при сохранении управляемых
метаданных. Его назначение официальной документацией не подтверждено.
DNS и неизвестная QoS-политика проверяются только при первоначальной привязке
порта к собственной ВМ. Замена уже известной политики запрещена.

Обезличенный [пример плана](../tests/fixtures/selectel-refresh-observed.json)
сохраняет формы наблюдённых полей; значения заменены синтетическими.
Исходные значения DNS и QoS не используются как подтверждение их происхождения.
Проверяется допустимость наблюдения, а не разрешение изменять эти параметры.

В [регрессионных тестах](../scripts/test_node_refresh.py) проверены
допустимое обновление, подмена ID и владельца, чужие привязки, неизвестные
поля, повреждённые ответы, DNS и QoS. Запланированные изменения, удаление
и замена ресурсов по-прежнему отклоняются. Полный локальный прогон:
560 тестов, 5443 из 5530 строк и 2000 из 2102 ветвей. Рабочий код не исключался.
Локальные тесты не подтверждают повторное применение в облаке.

Сохранённая
[диагностика es1](terraform-faults/es1-plan-guard-a94cc282521946cd9f86dc0f34b1ebad.json)
содержит имена полей, но не исходные значения; точная форма изменения
`scheduler_hints` не установлена. Добавлены безопасные сравнения структуры
до очистки: типы, пустота полей и соответствие группы сохранённому значению.
Допускается только семантически неизменная группа с пустыми необязательными
полями. Смена группы или дополнительные ограничения по-прежнему блокируются;
это не доказательство, что именно такая нормализация была в облачном плане.

В [облачном прогоне](test-cycle-result.json) после локального исправления
[все семь этапов инфраструктуры](repeat-infrastructure-result.json) повторно
применены с нулевыми изменениями. Защита `scheduler_hints` прошла на всех ES-узлах.
Повторная настройка служб прервана таймаутом и потерей SSH-соединения;
оператор сообщил об отключении Wi-Fi ноутбука. Это не устанавливает внутреннюю
ошибку Ansible. Ошибка DNS при автоматической очистке потребовала отдельного destroy.
Полный повторный deploy, итоговая проверка всех источников логов и Kibana
пока не подтверждены. Первичная настройка, сайт, SQL, media и запись контрольных
документов Elasticsearch прошли. [Очистка](cleanup-audit.json) подтверждена
через state и API; реквизиты доступа и кеш S3 сохранены.
