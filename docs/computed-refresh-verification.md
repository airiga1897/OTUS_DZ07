# Безопасное повторное применение Terraform

Повторный deploy сохраняет ID и размещение действующего стенда. План с удалением,
заменой или изменением существующего ресурса блокируется до apply. Обновление
наблюдаемых полей при чтении API рассматривается отдельно от запланированной записи.

Узкие допуски в [selectel_refresh.py](../scripts/selectel_refresh.py) проверяют
ID, владельца, сеть, адрес и связь порта с собственной ВМ. Для загрузочного тома
разрешено только обнаружение привязки к сохранённой ВМ, без смены типа диска,
размера или отсоединения. Метаданные не могут потерять маркер владельца.
DNS и QoS допускаются только как первоначально обнаруженные поля собственной
привязки; изменение уже известной политики блокируется.

Для `scheduler_hints` сравнивается сохранённая группа. Пустые необязательные
поля могут иметь эквивалентное представление; другая группа, дополнительные
непустые ограничения и неизвестные поля запрещены. Допуск обновления state
не разрешает Terraform изменять существующие ресурсы.

[Синтетический пример наблюдаемых форм](../tests/fixtures/selectel-refresh-observed.json)
и [регрессионные тесты](../scripts/test_node_refresh.py) проверяют корректные
и повреждённые данные, подмену ID, владельца и связей. Значения примера не являются
данными действующего стенда. [Полный локальный набор](local-quality.md)
проверяет контракты; [облачный цикл](current-cloud-acceptance.json) подтвердил
повторный deploy с сохранением ресурсов и данных в ru-2.

При отклонении плана сохраняется обезличенная диагностика перед очисткой
временного test-cycle. Обычный deploy оставляет данные восстановления.
[Правила диагностики и удаления](operations.md).
