# Подбор размещения Selectel

Предпочтения и ограничения находятся в [.env.example](../.env.example),
локальном `.env` и [config/placement.json](../config/placement.json).
По умолчанию: ru-2 → ru-9 → ru-3, затем остальные разрешённые пулы API.
[Полный список параметров и исключений](run-settings.md).
Изменение предпочтений не переносит уже созданные ресурсы.

## Совместимое сочетание

До создания ресурсов проверяются пул, вычислительный сегмент, сегмент диска,
сетевые домены, образ, конфигурация ВМ, возможности, квоты и конфликт подсетей.
Наличие отдельных элементов каталога не доказывает совместимость сочетания
и не гарантирует свободные физические хосты. Ошибка API не означает отсутствие
поддержки. Причина отклонения выводится до перехода к следующему кандидату.

Пулы проверяются последовательно, каталоги повторно используются внутри
одного запуска. Созданные узлы сохраняются. При подтверждённой нехватке хостов
очищается только неудачная попытка; следующий кандидат разрешён после аудита
её state и API. [Жизненный цикл этапов](distributed-placement.md).

## Сеть и сегменты

Вычислительный сегмент, привязка диска и зона планирования сетевых служб —
разные параметры. Внутри пула ВМ используют L2-связность приватной сети.
Для `ru-3b` задано соответствие: ВМ и диск — `ru-3b`, сеть и облачный
маршрутизатор — `ru-3a`. Соответствие проверяется по API и ограничено одним пулом.
Совпадения суффиксов имён недостаточно.

Для остальных сегментов выбирается точный домен API либо единственный обычный
домен своего пула. Неоднозначные варианты, чужие пулы и `*-paas` не выбираются
автоматически. Явные соответствия также проверяются. Terraform получает отдельные
параметры зоны ВМ, сети и маршрутизатора; они сохраняются в привязке state.

Однопуловый стенд не требует Глобального роутера. Перед ресурсами во втором пуле
проверяются общая группа зон, доступ и квоты подключений. Уже созданный роутер
сохраняется. [Условное подключение](adr/0010-conditional-global-router.md).

## Диски и образы

Порядок масок — `universal.*`, затем `basicssd.*`. Привязка типа к сегменту
подтверждается `RESKEY:availability_zones` в `extra_specs`. Неизвестный тип
пропускается без исключения остальных проверенных типов зоны. HDD и
`universal2.*` автоматически не добавляются.

Учтено ограничение выбора дисков из ДЗ05–ДЗ06: тип, доступный в пуле ru-3,
не обязательно доступен в каждом его сегменте. Например, `basicssd.ru-3b`
нельзя использовать для ВМ в ru-3a. ДЗ07 проверяет это собственным кодом,
без обращения к соседним проектам при работе.

Требуется точное имя `Ubuntu 24.04 LTS 64-bit`, публичный активный образ,
`os_distro=ubuntu`, совместимая архитектура и допустимые min_disk/min_ram.
Разрешённые MD5 Glance `checksum` хранятся только в `image_checksums`
конфигурации размещения. Имя без разрешённой суммы недостаточно;
разрешённая сумма не отменяет остальные проверки. [Причины исключений](pool-catalog-audit.md).

## Подтверждения

[Полный облачный цикл](current-cloud-acceptance.json) подтвердил ru-2,
разнесение ES по трём физическим хостам, сайт, логи, Kibana, повторный deploy
и удаление. [Локальные тесты](local-quality.md) проверяют маски, формы ответов,
несовместимые сегменты, ошибки API и сохранение размещения. Переход между пулами
и каждое альтернативное сочетание этим облачным циклом не подтверждены.

Официальные описания: [пулы и L2-связность](https://docs.selectel.ru/infrastructure/locations/),
[приватные сети](https://docs.selectel.ru/cloud-servers/cloud-networks/private-networks-and-subnets/),
[сетевые диски](https://docs.selectel.ru/cloud-servers/volumes/about-network-volumes/).
