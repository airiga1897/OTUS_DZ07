# Доставка исходников и пакетов

Способ задаётся явно полем `artifact_delivery` в
[config/services.json](../config/services.json). Общий код использует отдельные
коннекторы: [GitHub Releases](../scripts/release_artifacts.py) и
[S3](../scripts/s3_artifacts.py). Автоматического fallback между ними нет.
При ошибке выбранного источника развёртывание останавливается.

| Режим | Исходники | Пакеты Elastic | Назначение |
| --- | --- | --- | --- |
| `release` | Архив точного коммита из GitHub Release | Файлы того же выпуска | Основной способ сдачи, без доступа к S3 автора |
| `s3` | Версия текущего рабочего дерева в приватном бакете | Повторно используемые объекты по хешам | Отдельный способ разработки |
| `cached` | Передача текущего кода по SSH | Проверенный локальный кэш по SSH на es1, затем приватная сеть | Явное испытание без публикации исходников |
| `internet` | Передача текущего кода по SSH | Загрузка официальных пакетов на ВМ | Требует доступности официального источника из облака |

Release закрепляет коммит, манифест, размеры и SHA512. Контрольные суммы
пакетов находятся в [config/elastic-artifacts.json](../config/elastic-artifacts.json).
Подписанные ссылки, ключи и служебный манифест в Git не попадают.
[Самостоятельный запуск проверяющим и сборка выпуска](releases.md).

## Разработка через приватный S3

S3 позволяет доставлять ещё не опубликованные исходники по HTTPS и не
передавать крупные пакеты с ноутбука при каждом развёртывании. Это дополнительный
коннектор разработки; основной режим `release` его не использует.
Готового бакета автора сценарий не требует и не предполагает.

Создайте собственный приватный бакет Selectel Object Storage без Object Lock
и отдельный S3-ключ. В разделе `s3` файла
[config/artifacts.json](../config/artifacts.json) задайте его endpoint, пул,
имя, префикс `otus-dz07` и срок ссылок 300–3600 секунд. ВМ по-прежнему не могут
размещаться в исключённом ru-7; пул Object Storage выбирается независимо.
Endpoint использует HTTPS, адресация — Virtual Hosted.

Ключу нужны операции чтения, загрузки, удаления и составных загрузок объектов
своего префикса. Проверка закрытости и очистка дополнительно читают политику,
ACL и настройки/перечень версий бакета. Широкое разрешение всем пользователям
отклоняется. Включение публичного доступа не является способом устранить ошибку.

Введите ключи скрыто, без передачи в чат или записи в конфигурацию:

```powershell
. .\scripts\env.ps1 -Artifacts
# Явный режим разработки с сохранением:
# . .\scripts\env.ps1 -Artifacts -SaveLocal
# Явная загрузка в другой сессии:
# . .\scripts\env.ps1 -Artifacts -Development

# Проверка загрузки, HTTPS-скачивания с хешем и удаления тестового объекта
.\.tools\venv\Scripts\python.exe scripts/s3_artifacts.py verify
```

Python получает ключи только из окружения. Локальное сохранение выполняет
PowerShell с проверкой владельца и прав. Для режима `s3` требуются заранее
подготовленные и проверенные пакеты в `.tools/elastic-packages`. Перед deploy
выберите `s3` в конфигурации; пакеты используются повторно по хешам, новая
версия исходников получает свой объект. ВМ скачивают файлы по временным HTTPS-ссылкам.

## Очистка артефактов

Обычный destroy сохраняет объекты разработки. Отдельная команда удаляет
стенд и все принадлежащие ДЗ07 объекты, версии и незавершённые составные загрузки
в подтверждённом префиксе S3. Сам бакет сохраняется:

```powershell
.\.tools\venv\Scripts\python.exe scripts/lab.py destroy --purge-artifacts
```

До удаления проверяются привязка бакета и отсутствие действующих потребителей.
Неизвестное владение или ошибка API блокируют успешное подтверждение очистки.
Реквизиты разработки удаляются отдельно по решению пользователя.
