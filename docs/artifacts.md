# Доставка исходников и пакетов

Основной сценарий использует [GitHub Releases](releases.md). Для него не нужны
бакет, S3-ключи или обращения к S3 API. Ошибка Release останавливает доставку,
автоматического перехода на другой источник нет.

## Дополнительный коннектор S3

Коннектор S3 сохранён для разработки: закрытого размещения неопубликованных
версий исходников и повторного использования проверенных крупных пакетов.
Это позволяет ВМ получать файлы по временным HTTPS-ссылкам без публикации кода
и передачи постоянных ключей хранилища на серверы. Для включения нужны собственный
приватный бакет и явный выбор `artifact_delivery: s3` в `config/services.json`.
Поле `s3.bucket` в `config/artifacts.json` по умолчанию пустое; действующего
хранилища разработки проект не предполагает.

Оба коннектора реализуют `prepare(root)` и возвращают одинаковый манифест.
[`delivery.py`](../scripts/delivery.py) выбирает только указанный режим.
GitHub Releases реализован в [`release_artifacts.py`](../scripts/release_artifacts.py),
S3 — в [`s3_artifacts.py`](../scripts/s3_artifacts.py); общие проверки хешей,
списка пакетов и снимка исходников находятся в
[`artifact_content.py`](../scripts/artifact_content.py).
Release, передача файлов и определение версии операции Ansible не импортируют
S3-коннектор. Служебная очистка подключает его только при наличии собственных
S3-маркеров или явном запросе S3-операции.

При использовании S3 текущие исходники
упаковываются в воспроизводимый архив, а проверенные пакеты Elasticsearch,
Filebeat и Kibana сохраняются как неизменяемые объекты. Ключ объекта содержит
SHA512: одинаковые файлы используются повторно, изменённый код создаёт новую версию.
Исходники включают код и несекретные настройки; служебные файлы, state,
реквизиты, ключи, media и база данных в архив не входят.

ВМ получает по SSH только небольшой загрузчик, параметры своего узла,
прикладные секреты и временные HTTPS-ссылки. Архив исходников и пакеты она
скачивает сама. Ссылка разрешает чтение конкретного объекта в течение часа;
S3-ключ на ВМ не передаётся. Перед использованием проверяются размер и SHA512.
Ошибки доступа, истечение срока ссылки и несовпадение хеша останавливают настройку.
Загрузчик читает поступающие данные через `read1` блоками до 64 КиБ, сообщает прогресс и ограничивает
ожидание сетевого чтения 30 секундами. Общий предел на файл — 30 минут;
он проверяется между чтениями. При сетевом сбое допускаются до трёх попыток
в пределах этого срока, каждая начинает передачу заново. Ошибки доступа и
несовпадение хеша не повторяются. Прежний файл заменяется только после полной
проверки размера и SHA512; незавершённая копия удаляется при ошибке.
Подписанные ссылки удаляются с ВМ после загрузки, не включаются в доказательства
и не публикуются. При следующем развёртывании ссылки выпускаются заново.

## Подготовить Selectel S3

1. В панели Selectel выберите проект разработки, затем **S3 → Бакеты → Создать бакет**.
2. Укажите уникальное имя без точек, например `otus-dz07-artifacts-<суффикс>`.
   Выберите доступный пул, **приватный** тип, стандартное хранение и Virtual-Hosted
   адресацию. Не включайте публичную раздачу или веб-сайт. Object Lock для этого
   сценария не требуется; версии исходников различаются по хешу объекта.
3. Подготовьте сервисного пользователя с доступом только к нужному проекту
   и бакету. Если применяется политика бакета, выдайте разрешения конкретному
   пользователю, без анонимных и широких разрешений. Нужны чтение объектов,
   загрузка с приватным ACL, чтение ACL и политики бакета. Для ограниченных
   ролей `s3.user`/`s3.bucket.user` доступ задаётся политикой бакета.
4. В **IAM → Сервисные пользователи** откройте пользователя и выдайте ему S3-ключ.
   Ключ другому пользователю выдаёт владелец аккаунта или пользователь `iam.admin`.
   Пара Access Key ID / Secret Key отличается от пароля OpenStack.
5. Запишите имя бакета, пул и S3 API endpoint в
   [config/artifacts.json](../config/artifacts.json). Endpoint относится к бакету,
   не к пулу вычислительных ВМ; смена размещения стенда его не меняет.
   Поддерживается Virtual-Hosted адресация; настройки endpoint и пула должны
   соответствовать созданному пользователем бакету.
   Это не разрешает размещение ВМ в ru-7: политика вычислений хранится отдельно
   в [config/placement.json](../config/placement.json). Реальные ключи в конфигурацию не записываются.

Официальные инструкции: [создать бакет](https://docs.selectel.ru/s3/buckets/create-bucket/),
[доступ к S3](https://docs.selectel.ru/s3/about/manage-access/),
[выдать ключ](https://docs.selectel.ru/access-control/manage/edit-user-data-or-role/),
[временные ссылки](https://docs.selectel.ru/s3/objects/obtain-link-to-object/).

## Подготовить артефакты разработки

Команды выполняются в PowerShell из корня ДЗ07 после `scripts/setup.ps1`.

```powershell
# Скрытый ввод S3-ключа в окружение текущего процесса, без записи файла
. .\scripts\env.ps1 -Artifacts

# ИЛИ явное сохранение ключей разработки с доступом только текущему пользователю
. .\scripts\env.ps1 -Artifacts -SaveLocal

# ИЛИ явная загрузка сохранённых S3-ключей
. .\scripts\env.ps1 -Artifacts -Development

# Отдельно подтвердить проект обычным env.ps1 или явным режимом разработки
. .\scripts\env.ps1 -Development

# Проверить загрузку, HTTPS-скачивание, SHA512 и удаление тестового объекта
.\.tools\venv\Scripts\python.exe scripts/s3_artifacts.py verify

# Полностью скачать все три пакета и проверить их закреплённые SHA512
# Объекты в S3 сохраняются; временные локальные копии удаляются автоматически
.\.tools\venv\Scripts\python.exe scripts/s3_artifacts.py verify-packages

# Проверить/загрузить артефакты и выпустить временные ссылки; ВМ не создаются
.\.tools\venv\Scripts\python.exe scripts/s3_artifacts.py
```

Схема полей S3 находится в [config/artifact-auth.json](../config/artifact-auth.json).
Python читает ключи только из окружения; стандартные AWS-профили и файлы
автоматически не используются. Ключ `-Artifacts` выбирает только схему S3;
без него вводятся OpenStack-реквизиты. `-SaveLocal` и `-Development` несовместимы.
S3-ключи сохраняются только по явному запросу в
`.local/artifact-credentials.json`; перед чтением проверяются владелец и ACL.
Оба файла разработки исключены из Git, при `destroy` не удаляются и очищаются
пользователем отдельно. OpenStack-файл `operator.json` при работе с S3 не меняется.
`env.ps1 -Clear` удаляет оба набора переменных из текущей сессии.

Первичная загрузка требует трёх проверенных `.deb` в `.tools/elastic-packages`.
Их SHA512 закреплены в [config/elastic-artifacts.json](../config/elastic-artifacts.json)
по ранее полученным официальным контрольным суммам. При отсутствии файлов
можно явно импортировать каталог с пакетами и соответствующими `.sha512`:

```powershell
.\.tools\venv\Scripts\python.exe scripts/cache_packages.py --source C:\Packages\Elastic
```

Затем `scripts/s3_artifacts.py` проверяет файлы по закреплённым хешам и загружает
только отсутствующие объекты. Доступ к чужому объекту, ошибка чтения метаданных
и несовпадение существующего объекта не считаются разрешением на перезапись.
Публичный ACL или широкая разрешающая политика отклоняются. Подписанный манифест
остаётся в исключённом из Git `.local/artifact-delivery.json`; обычный `deploy`
подготавливает его автоматически до создания вычислительных ресурсов.

## Жизненный цикл и границы проверки

Бакет — постоянное хранилище разработки. Обычные `destroy` и `test-cycle`
удаляют временный стенд и маркер своего запуска, сохраняя версии исходников и
пакеты для повторного использования. Перед локальной очисткой проверяются
пустой state и отсутствие ресурсов через облачный API. Затем удаляются
SSH-ключи, прикладные секреты и временные ссылки. Несекретная привязка
`.local/artifact-storage.json` сохраняет проект, endpoint, бакет и префикс.

Для полной очистки файлов ДЗ07, в том числе после обычного `destroy`:

```powershell
# Необратимо удалить стенд и все артефакты в его подтверждённом префиксе
.\.tools\venv\Scripts\python.exe scripts/lab.py destroy --purge-artifacts
```

Расширенная очистка выполняется только после подтверждения удаления стенда.
Она удаляет объекты, версии, маркеры удаления и незавершённые составные загрузки
в `otus-dz07/`, затем повторно проверяет их отсутствие. Объекты за пределами
этого префикса и сам бакет сохраняются. Если есть маркер другого действующего
запуска, удаление артефактов отклоняется. При ошибке команда завершается
неуспешно, привязка и `.local/artifact-purge-pending.json` остаются для повтора.
Результат записывается в `docs/s3-cleanup.json`, без реквизитов и временных ссылок.

На бакет нужны `s3:GetBucketAcl`, `s3:GetBucketPolicy`, `s3:GetBucketVersioning`,
`s3:ListBucket`, `s3:ListBucketVersions`, `s3:ListBucketMultipartUploads`.
На объекты `otus-dz07/*` нужны чтение/загрузка/удаление,
`s3:GetObjectAcl`, `s3:PutObjectAcl`, `s3:DeleteObjectVersion`,
`s3:AbortMultipartUpload`, `s3:ListMultipartUploadParts`.
Область прав не расширяется на чужие бакеты.

В Windows SDK использует доверенные CA системного хранилища, как стандартные
HTTPS-запросы Python. Проверка имени сервера и цепочки TLS не отключается;
публичная копия системных CA находится в `.tools/system-trust-ca.pem`.

Локальные тесты проверяют сборку архива без служебных данных, повторное
использование пакета, отклонение широких ACL, проверку хеша/размера и защиту
распаковки, привязку области очистки и сохранение файлов другого запуска.
Результат реальной проверки загрузки/скачивания/удаления фиксируется отдельно
в `docs/s3-probe.json`. Наличие такого теста не подтверждает развёртывание ВМ
через S3: оно требует отдельного завершённого облачного прогона.

Подготовка полного набора проверяется отдельно в
[s3-delivery-verification.json](s3-delivery-verification.json): загрузка трёх
пакетов и исходников, повторное использование без новой загрузки и очистка
временного маркера. Полное скачивание каждого пакета с проверкой размера и
закреплённого SHA512 выполняет `verify-packages`; результат сохраняется в
[s3-package-downloads.json](s3-package-downloads.json). Эта проверка выполняется
на компьютере оператора и не заменяет отдельную проверку доставки на ВМ.

## Самостоятельное развёртывание проверяющим

Режим `release` получает архив исходников и все три проверенных пакета из
конкретного GitHub Release. Манифест закреплён SHA512; размеры и хеши файлов
проверяются перед распаковкой и установкой. Ключи и бакет S3 не используются.
Сборщик работает только с чистым закоммиченным деревом и создаёт локальные
файлы выпуска; он не выполняет публикацию. [Подготовка выпуска и запуск из
чистого клона](releases.md). Публикация ещё не выполнена; облачная доставка
этим каналом не подтверждена.
