# Выполнение Ansible и восстановление связи

Настройка запускается на app как отдельная systemd-операция, независимо
от SSH-сессии. ID сохраняется в `.local/ansible-operation.json` до возможной
отправки команды запуска и связывается со стендом, ID app, исходниками
и параметрами. Контекст содержит хеши приватных входных файлов, не их значения.

## Состояния и восстановление

| Состояние | Значение |
| --- | --- |
| `preparing` | Операция зарезервирована, Ansible ещё не запущен |
| `running` | Сервис или дочерние процессы работают |
| `succeeded` | Получен атомарный результат с кодом 0, сервис завершён |
| `failed` | Получен ненулевой код, в том числе при таймауте операции |
| `stopped` | Явная остановка подтверждена |
| `unknown` | Связь недоступна или результат отсутствует/повреждён |

После восстановления связи повторите команду в том же клоне с прежними
исходниками и параметрами:

```powershell
. .\scripts\env.ps1
.\.tools\venv\Scripts\python.exe scripts/lab.py deploy
```

Контроллер сверяет привязку и наблюдает тот же ID. Потеря ответа о запуске
не разрешает запуск замены: проверяется прежний systemd unit. Блокировки
запрещают параллельную настройку. Несовпадение исходников, inventory или ВМ
блокирует продолжение; неизвестный результат не считается успехом или ошибкой
Ansible. После подтверждённой ошибки и завершающих действий следующий явный
deploy может начать новую операцию.

Параметры времени находятся в [config/stack.json](../config/stack.json):
лимит самой операции и ожидание подключения разделены. Сетевой таймаут
не выдаётся за код завершения Ansible. Ошибка завершающих действий сохраняет
первоначальную причину сбоя. Не удаляйте контекст и ключи до подтверждённой очистки.

## Ход задач

Штатный notification callback пишет `events.jsonl` в каталоге ID операции
на app. Используются последовательные номера; контроллер получает ограниченные
порции, не читает незавершённую последнюю строку и сохраняет позицию в контексте.
После обрыва или перезапуска наблюдение продолжается без нового Ansible.

INFO показывает узел, статическое название задачи и результат: начало, ok,
changed, failed, skipped. Аргументы, переменные, stdout/stderr и содержимое
результатов модулей не передаются. Для `no_log` скрыты название и результат.
Неопределённый no_log, шаблонные и небезопасные названия также скрываются.
Текст консоли регулярными выражениями не разбирается.

Если новых событий нет или чтение временно недоступно, INFO сообщает последнее
подтверждённое состояние. WARNING используется для установленной проблемы
наблюдателя с безопасной причиной; длительность сама по себе не повышает уровень.
Ошибка прогресса не останавливает Ansible, не вызывает повторный запуск и
не заменяет итоговый результат операции.

При аварии между печатью события и сохранением позиции часть сообщений
может повториться. Строго однократный вывод не гарантируется.

## Защита и удаление

Каталоги операций имеют режим `0700`, файлы — `0600`. Результат с временем
начала/окончания и кодом записывается атомарно. Inventory, ключи и управляющие
данные передаются приватными файлами; реквизиты оператора и S3 на ВМ не отправляются.
Публичный [результат операции](ansible-operation-result.json) не содержит
inventory, хешей параметров или сырого журнала.

Перед удалением app контроллер подтверждает завершение либо явно останавливает
собственную операцию и её дочерние процессы. Неизвестная остановка блокирует
удаление, сохраняя state и ключи. После восстановления связи повторяется destroy.
Обычный deploy не очищает стенд при ошибке; test-cycle очищает только свои
ресурсы и при недоступном управлении оставляет данные для продолжения.

## Подтверждения

[Облачный цикл текущего кода](current-cloud-acceptance.json) подтвердил первый
и повторный запуск через systemd и отображение задач. [Локальные проверки](local-quality.md)
покрывают потери ответа, восстановление соединения, перезапуск контроллера,
повреждённые результаты и события, чужую привязку, no_log, остановку и ошибки
диагностики. Намеренное отключение реальной сети в облаке не выполнялось.
[Callback API Ansible](https://docs.ansible.com/projects/ansible-core/2.18/plugins/callback.html).
