# Настройки запуска

`scripts/setup.ps1` создаёт `.env` в корне клона по [.env.example](../.env.example),
если локального файла ещё нет. Существующий `.env` не перезаписывается.
Файл исключён из Git. Без локального файла используются значения примера.

Единственный загрузчик — [run_settings.py](../scripts/run_settings.py).
Приоритет: `.env.example` → `.env` → одноимённые переменные текущей сессии.
Поддерживаются буквальные `ИМЯ=значение`, парные кавычки и комментарии отдельными
строками. Выполнение команд и подстановка переменных запрещены. Ошибки формата,
неизвестные ключи и недопустимые значения останавливают запуск до создания ресурсов.

| Параметр | Назначение |
| --- | --- |
| `REQUIRE_DISTINCT_HOSTS` | Обязательное размещение ES на разных физических хостах |
| `SELECTEL_PREFERRED_POOLS` | Пулы, проверяемые первыми; список не ограничивает обнаружение |
| `SELECTEL_EXCLUDED_POOLS` | Исключённые для ВМ пулы |
| `SELECTEL_EXCLUDED_SEGMENTS` | Исключённые вычислительные сегменты; пустое значение снимает этот список исключений |
| `SELECTEL_DISK_TYPE_PATTERNS` | Порядок масок допустимых типов дисков |
| `SELECTEL_FLAVOR_NAME_PATTERNS` | Порядок разрешённых масок имён конфигураций ВМ; `{vcpus}` и `{ram_mb}` берутся из профиля |
| `APP_VCPUS`, `APP_RAM_MB` | Параметры общей ВМ |
| `ES_VCPUS`, `ES_RAM_MB` | Параметры каждого узла Elasticsearch |
| `BOOT_DISK_GB` | Размер загрузочного диска каждой ВМ |

Значения по умолчанию определены в `.env.example`, без повторения в JSON.
Схемы реквизитов, сетевые соответствия, имена и структура приложения остаются
в `config/`. Пароли, токены, S3-ключи и реквизиты оператора в `.env` не записываются:
для них сохраняется интерфейс `scripts/env.ps1`.

## Размещение

Адаптер Selectel получает пулы из каталога API, исключает указанные пользователем
и сначала проверяет предпочтительные. По умолчанию это ru-2 → ru-9 → ru-3,
затем остальные совместимые пулы каталога.
Для ВМ исключены `ru-7`, `ru-4`, `ru-5`, `ru-6`, `kz-1`, `ke-1`, `gis-1`, `gis-2`, `uz-1`, `uz-2`.
В ru-4 и ru-5 не найден точный требуемый образ. Разрешённые MD5 образа
хранятся отдельно в `config/placement.json`, поле `image_checksums`;
пользовательские настройки запуска этот список не подменяют.
В списке задаются полные имена пулов. S3 в ru-7 используется отдельно;
исключения размещения ВМ на него не распространяются.

В ru-6 отсутствуют диски с разрешёнными масками `universal.*` и `basicssd.*`.
Вычислительный сегмент `ru-1b` исключён через `SELECTEL_EXCLUDED_SEGMENTS`:
доступные разрешённые диски не имеют привязки к нему. В ru-1c и ru-8a
каталоговые сочетания совместимы, поэтому они сохраняются в общем переборе.
Нулевые квоты ru-1a и ru-2b не превращаются в постоянные исключения:
перед запуском проверяются актуальные лимиты. Ошибка API не считается
доказательством несовместимости. Если каталоги изменятся, явные исключения
можно пересмотреть в `.env`; остальные проверки совместимости остаются обязательными.

Для каждой зоны перебираются все совместимые типы дисков из заданного списка,
а для каждого диска — разрешённые конфигурации ВМ. По умолчанию допускаются
`SL1.{vcpus}-{ram_mb}` и `SL2.{vcpus}-{ram_mb}-AMD`; точные vCPU/RAM сохраняются,
конфигурации с локальным диском не используются. Привязка конфигурации к зоне
проверяется по API. Наличие конфигурации в каталоге не гарантирует свободный
физический хост. Следующий кандидат применяется после очистки неуспешной
попытки с аудитом state и API; работающие узлы сохраняются.

Неизвестная привязка конкретного диска или некорректный список зон конкретной
конфигурации исключают только этот неподтверждённый вариант с указанием причины.
Остальные подтверждённые варианты продолжают проверяться. Ошибки доступа и
запросов API останавливают проверку: они не означают отсутствия поддержки.
Проверки полной схемы и отдельной сети используют единый резерв служебных
портов; доступность порта ВМ и публичного адреса app повторно проверяется
перед созданием узла.

Файлы читаются при начале команды. Изменение `.env` во время уже запущенного
подбора не меняет его сохранённые настройки. Переменные текущей PowerShell-сессии
имеют приоритет: если исключения были заданы вручную и устарели, удалите именно
`Env:SELECTEL_EXCLUDED_POOLS` перед следующим запуском, чтобы использовать `.env`.
Другие пулы допускаются после проверки полного сочетания образа, конфигурации,
дисков, сети и квот. Группа зон и квоты Глобального роутера проверяются при
необходимости размещения между пулами. Название пула не является
доказательством совместимости. Неизвестная возможность или ошибка API не
превращается в успешную проверку; для отклонённых кандидатов выводятся причины.

До создания сохраняются выбранная группа совместимых пулов и непересекающиеся
подсети. Сеть создаётся только при попытке разместить в ней ВМ; глобальное
подключение — после подтверждения успешной ВМ. Подробности:
[последовательное размещение](distributed-placement.md).

Параметры ВМ, дисков и режим разнесения сохраняются в служебном контексте.
Повторный deploy блокирует их изменение. Перестановка предпочтений не меняет
ID, адреса и размещение существующих узлов. Новый каталог API не расширяет
сетевой граф действующего стенда автоматически. Для destroy используются
сохранённые настройки даже при ошибке в текущем `.env`.

## Диагностическое совместное размещение

По умолчанию `REQUIRE_DISTINCT_HOSTS=true`. Для отдельно согласованного нового
диагностического стенда допустимо:

```dotenv
REQUIRE_DISTINCT_HOSTS=false
```

Блок `scheduler_hints` у ES-ВМ отсутствует. Управляемая группа Terraform
сохраняется, но эти ВМ в неё не включаются; она не ограничивает их размещение.
Проверка фиксирует режим и наблюдаемое количество хостов, не требует трёх
разных хостов и не заявляет подтверждение физического разнесения.
Проверки сети, Elasticsearch, данных, журналов и очистки сохраняются.
Такой прогон не подтверждает отказоустойчивость к потере физического хоста.
После удаления диагностического стенда следует вернуть `true`.

Параметры не меняют интерфейс команд: `deploy`, `verify`, `open`, `destroy`
и отдельный `test-cycle`. `.env` не включается в архив доставки исходников;
`.env.example` включается. Фактические настройки серверов передаются из
сохранённого результата развёртывания.

[Результаты локальных проверок](local-quality.md) подтверждают
настройки, ограничения повторного применения и порядок этапов на mock API.
Облачный цикл текущего кода проверял `REQUIRE_DISTINCT_HOSTS=true`;
он не подтверждает диагностический режим совместного размещения.
