# Локальные проверки качества

Используется виртуальное окружение проекта на Python 3.12. Подготовка
`scripts/setup.ps1` устанавливает закреплённые зависимости из
`requirements-quality.txt`. Реквизиты облака для проверок не нужны.

Из корня клона:

```powershell
.\.tools\venv\Scripts\python.exe scripts/check.py
```

Команда выполняет unittest контроллера и доставки, Django-тесты, pytest,
измерение строк и ветвей, Ruff, проверку форматирования Ruff и строгий mypy.
Проверки подставляют внешние API и SSH и используют временные каталоги.
Во время измеряемых тестов внешние подключения блокируются. Проверки
не являются подтверждением работоспособности новой версии в облаке.

Ruff использует `ruff.toml`, mypy — `mypy.ini`. Длина строки форматирования —
120 символов; правило E501 не дублирует форматирование. Black, isort и flake8
отдельно не запускаются: форматирование и правила импортов выполняет Ruff.
GitHub Actions для проекта не требуется.

Mypy проверяет весь набор исходников отдельно для `win32` и `linux`:
локальный контроллер использует Windows, исполнитель Ansible — Linux на app.
Проверка обеих платформ не исключает серверные модули и не скрывает обращения
к неподдерживаемым системным функциям. Ошибка любой проверки сохраняет
неуспешный результат; журнал содержит отдельный результат каждой платформы.
Это статический анализ, а не запуск Linux-операции на Windows.
Для callback используются узкие внешние описания типов в `typings/ansible`:
конструктор и обработчики `CallbackBase`, используемые поля `TaskResult`,
методы Host и Task. Интерфейсы сверены с исходниками закреплённого
[ansible-core 2.18.18](https://pypi.org/project/ansible-core/2.18.18/).
Они не заменяют Ansible и не устанавливают Linux-исполнитель на Windows.
При смене версии Ansible эти описания требуют повторной сверки.
Типы необязательного S3-коннектора устанавливаются через закреплённые
`boto3-stubs[s3]` и `mypy-boto3-s3`; проверка не обращается к бакету.
Кэши платформ разделены внутри `.tools/quality`, чтобы переключение целевого
окружения не вызывало повторный анализ неизменённых файлов.
Автоматическая замена `str, Enum` на `StrEnum` (UP042) отключена: она меняет
строковое представление существующего перечисления.

В правиле именования сохранены десять существующих имён исключений,
перечисленных в `ruff.toml`: они используются на границах восстановления
и в диагностике. Это точечное исключение из требования суффикса `Error`;
оно не исключает их код из остальных правил, mypy или измерения покрытия.

Для отдельного статического анализа:

```powershell
.\.tools\venv\Scripts\python.exe scripts/quality.py
.\.tools\venv\Scripts\python.exe scripts/quality.py ruff format mypy
```

Контроллер проверки передаёт инструментам ограниченное окружение без реквизитов
облака. Код завершения, длительность и журналы сохраняются в `.tools/quality`.
Результаты тестов и покрытие — в `.tools/coverage`. Ошибка инструмента
не превращается в успешную проверку и не скрывается успешными тестами.

Из измерения исключены тесты, миграции Django и измеряющий скрипт. Объявления
Protocol без реализации обрабатываются стандартными правилами Coverage;
рабочие реализации ради достижения процента не исключаются. Измерение включает
неимпортированные Python-модули в каталогах без `__init__.py`.

Локальные hooks определены в `.pre-commit-config.yaml`. После завершения
настройки их проверяют командами:

```powershell
.\.tools\venv\Scripts\python.exe -m pre_commit install
.\.tools\venv\Scripts\python.exe -m pre_commit run --all-files
```

## Подтверждённый локальный результат

Полная команда проверена на текущих незакоммиченных исходниках. Это не результат
опубликованного Release и не облачное подтверждение.

| Проверка | Фактический результат |
| --- | --- |
| unittest скриптов | 819 успешно |
| unittest каталога tests | 66 успешно |
| Django | 26 успешно |
| pytest | 556 успешно |
| Строки рабочего Python-кода | 8524 из 8524, 100% |
| Ветви рабочего Python-кода | 2840 из 2840, 100% |
| Ruff | Успешно |
| Форматирование Ruff | 257 файлов, успешно |
| Строгий mypy | 1509 сообщений в 123 файлах для каждой платформы; проверено 257 файлов, ошибка |
| pre-commit | Ruff проходит; mypy блокирует успешный результат |

В тестах проверяется доставка текущего кода и всех пакетов из изолированного
локального Release в чистый Git-клон без S3 и внешних подключений. Отдельно
проверено чтение старой топологии БД для удаления: desired-конфигурация не
перестраивается и настройка Patroni/etcd не запускается. Это не испытание
удаления старых ресурсов через настоящий API.

Coverage также показывает 205 исключённых строк объявлений Protocol и блоков
`TYPE_CHECKING`. Отдельный тест проверяет, что объявления Protocol не содержат
реализации. Остальные исключения области измерения перечислены выше.

Сейчас полный набор после рефакторинга не проходит. Цель готовности — фактические
100% строк и ветвей рабочего кода, чистые Ruff и mypy и повторный успешный запуск
`scripts/check.py`. Процент покрытия не заменяет проверки внешних форм данных,
восстановления операций, владения ресурсами и безопасности удаления.
